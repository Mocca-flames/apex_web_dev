# Plan: Fix Values Section "Content is not Visible"

## Root Cause

**Timing bug in `content.js` + `reveal.js` interaction:**

1. `content.js` line 637–643: calls `buildAll()` and immediately fires `apexContentReady` event
2. `reveal.js` has `defer` attribute — it loads and runs **after** `content.js` has already fired the event
3. When `reveal.js` finally registers its `apexContentReady` listener, the event has already fired and passed
4. Principle cards have `.reveal` class but never receive `.is-visible` → stuck at `opacity: 0`

## Fix

Modify `content.js` to fire `apexContentReady` inside a `setTimeout(..., 0)` so it's deferred to the next event loop tick. By that point, all `defer` scripts (including `reveal.js`) will have registered their listeners before the event fires.

**File:** `js/content.js` line 643

```javascript
// BEFORE (fires synchronously before reveal.js loads)
var contentPromise = fetchContent().then(function(data) {
  if (data) {
    buildAll();
  } else {
    console.warn('[Apex Content] No content data loaded; dynamic content will be missing');
  }
});
window.apexContentReady = contentPromise;

// AFTER (deferred to next tick, reveal.js will be ready)
var contentPromise = fetchContent().then(function(data) {
  if (data) {
    buildAll();
  } else {
    console.warn('[Apex Content] No content data loaded; dynamic content will be missing');
  }
});
window.apexContentReady = contentPromise;

// Fire after current execution context so deferred scripts register first
setTimeout(function() {
  document.dispatchEvent(new Event('apexContentReady'));
}, 0);
```

## Verification

After fix:
- Open page → Values section shows cards (no JS needed for reveal)
- Cards fade in when IntersectionObserver fires (if motion allowed)
- No other sections affected
- No regressions

## Alternative Considered

Make Values section static HTML (no JS dependency). Not implementing — the dynamic architecture is correct, only the timing was broken.
