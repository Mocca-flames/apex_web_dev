# Fix Services Scroll-Jacking Not Working

## Problem
The Services scroll-driven section is not working, while the Coverage section works perfectly - even on mobile.

## Root Cause Analysis
Comparing `services.js` with `coverage.js` reveals critical missing features:

### 1. Missing `_bootGuard` (page-load race guard)
- **Coverage.js line 28**: Has `_bootGuard = true` to discard the very first `onScroll()` call during page-load before layout is stable
- **Services.js**: Does NOT have this guard, causing potential race conditions

### 2. Missing `IntersectionObserver` (primary visibility detection)
- **Coverage.js lines 139-161**: Uses IntersectionObserver as the PRIMARY detection method that observes the `track` element
- **Services.js**: Relies SOLELY on scroll events - has no IntersectionObserver fallback

### 3. MutationObserver doesn't update NodeList references
- **Coverage.js lines 124-136**: Updates `slides` and `labels` variables when DOM mutates
- **Services.js lines 261-267**: Does NOT update `panels` and `images` variables - only re-queries inside `activateService()`

## Fix Implementation

### Step 1: Add `_bootGuard` to services.js
Add a boot guard flag (same as coverage.js) to discard the first scroll event during page-load:
```javascript
var _bootGuard = true;  // discard very first onScroll call (page-load race)
```
And in `onScroll()`:
```javascript
if (_bootGuard) { _bootGuard = false; return; }
```

### Step 2: Add IntersectionObserver to services.js
Add an IntersectionObserver (similar to coverage.js) that observes the `.services-track` element as the PRIMARY visibility detection. This ensures the sticky section is properly shown/hidden when it enters/exits the viewport.

### Step 3: Fix MutationObserver to update NodeList references
Update the MutationObserver in services.js to refresh the `panels` and `images` variables when DOM mutations occur (same pattern as coverage.js).
