# Coverage-Slide Click-Blocking Fix

## Problem Statement

When `.coverage-slide.is-active` is shown, the entire page coverage feature is active and
all 8 slides are rendered in the DOM. The user can visually see ALL elements, but clicking
buttons does not have any effect.

## Root Cause Analysis

### CSS stacking structure

```
.coverage-sticky [position:fixed, z-index:10, overflow:hidden, isolation:isolate]
  └── .coverage-journey__slides [position:relative, height:100%]
        ├── .coverage-slide (active) [opacity:1, pointer-events:auto, z-index:2]
        ├── .coverage-slide (non-active) [opacity:0, pointer-events:none, z-index:auto]
        │     … 6 more non-active slides, same z-index:auto, opacity:0
        └── .coverage-progress [position:absolute, z-index:10]
```

In a stacking context created by `isolation: isolate`:

| Stacking order inside `coverage-sticky` (`isolation: isolate`) | z-index |
|---|---|
| `.coverage-progress` | 10 _(position: absolute)_ |
| `.coverage-slide.is-active` | 2 |
| `.coverage-slide:not(.is-active)` × 8 | `auto` → normalised to **0** |

### Why buttons don't receive clicks

`.coverage-sticky` with `position: fixed; z-index: 10` covers the full 100vh × 100vw viewport
regardless of the parent's page scroll position. When it has `.is-visible`, the element becomes
`opacity: 1; pointer-events: auto`, making it a **true full-viewport click-capturing overlay**.

Browser hit-testing for a mouse click resolves to exactly **one** leaf element. The traversal
enters every positioned ancestor — including `.coverage-sticky` — and stops at the topmost
element under the pointer. Because `.coverage-sticky` is fixed at `top: 0` and covers the full
viewport, every click inside the coverage area resolves through it first.

Inside `coverage-sticky`, the non-active slides all share the **same z-index: auto (→ 0)**
but are rendered in DOM order: each subsequent slide sits **visually on top** of the previous
one. Although they render invisible (`opacity: 0`), hit-testing still lands on the **topmost
DOM slide**, then translates the event into the corresponding `.coverage-slide` element.

The active slide fixations:

1. **`pointer-events: none` is ONLY on `.coverage-slide:not(.is-active)` by default**.
   During the transition call `setActive()` → old slide Toggles `.is-active` OFF (gains
   `.is-leaving`, `pointer-events: auto` for the 0.4 s fade-out), new slide Toggles
   `.is-active` ON (`pointer-events: auto`). Both slides momentarily have **`pointer-events:
   auto`**. The old slide (`z-index: 1`) sits underneath the new slide (`z-index: 2)`) so
   clicks would resolve to the new active slide anyway — **this looks fine in theory**.

2. **BUT**: the `z-index` of non-active slides is absent (auto). The spec says non-positioned
   positioned elements normally prefer siblings over a positioned element with `z-index:auto`
   (auto becomes 0). This means even a `z-index: 2` active slide CAN be visually below a
   non-active slide at `z-index: auto` that renders inside on top — **the active slide appears
   below an invisible glass slide**.

3. **Even without that stacking reversal**, `.coverage-sticky` with `pointer-events: auto`
   and `.coverage-journey__slides` as its only child means any click in its hit area, even on
   supposedly `hidden` (`pointer-events: none`) children, needs to pass through. In
   `components.css` only `.coverage-slide:not(.is-active)` sets `pointer-events: none` —
   not the parent `.coverage-journey__slides`. Because all 8 non-active slides have no
   positioned ancestor with `pointer-events: none`, the clickable region stays active.

### Why `pointer-events: none` fixes don't currently work

The inline injection used for non-index pages:
```css
.coverage-sticky { pointer-events: none !important }
.coverage-sticky.is-visible { pointer-events: auto !important }
```
ensures clicks pass through the sticky entirely. This is the right approach for non-coverage
pages, but it also fixes the symptom on the coverage page. **The correct structural fix needs
to sit in `components.css`.**

## Fix Plan

### 1. Components.css — Fix coverage-slide z-index and pointer-events
`css/components.css`

```css
/* Individual slide — fix non-active z-index and pointer-events */
.coverage-slide {
  position: absolute;
  inset: 0;
  display: flex;
  align-items: center;
  justify-content: center;
  gap: var(--space-24);
  padding: var(--space-20);
  opacity: 0;
  pointer-events: none;            /* ← already here */
  transition: opacity 0.6s ease-out;
  will-change: opacity;
  z-index: 1;                      /* ← ADD: explicit z-index below active slide */
}

.coverage-slide.is-active {
  opacity: 1;
  pointer-events: auto;
  z-index: 2;
}
```

Adding explicit `z-index: 1` on non-active slides gives them a predictable stacking value
within the `isolation: isolate` mode so they never compete with the active slide at
`z-index: 2`. The active slide is always **physically** on top.

### 2. Components.css — Guard coverage-sticky pointer-events on non-active children
`css/components.css`

Add `pointer-events: none` to `.coverage-slide:not(.is-active)` so the **container hierarchy**
does not accidentally carry pointer-events through any interim states. The core rule (already
present) is sufficient but reinforcing it after the `is-active` rule removes ambiguity:

```css
/* ─── NONE OF THE ABOVE: --- */
.coverage-slide:not(.is-active) {
  pointer-events: none;
}
```

This is already present at l1062 (the base `.coverage-slide` rule), but confirming it is
present prevents browsers from resetting the value during class mutations.

### 3. Index.html — No change needed
`index.html`

`index.html` does **not** contain the inline `<style>.coverage-sticky{pointer-events:none!important}…</style>`
workaround that the other pages use. The coverage section IS the intended feature here, so this page
must keep `.coverage-sticky.is-visible { pointer-events: auto }` active so the coverage overlay
handles clicks correctly on its own slide content.

## Verification Steps

1. **Index page — coverage section active**: scroll to the coverage section. Confirm the
   active slide title, text, and map image display at full opacity. Click inside the active
   slide frame (map image area) — click event must land on the `<img>` without being swallowed
   by any invisible sibling overlay.
2. **Index page — inside coverage section, non-active slide area**: click in an area of the
   viewport that corresponds to a non-active slide position (e.g. the lower half of the map
   frame for a different slide). The click must resolve to the active slide's content (`z:2`)
   and NOT be consumed by a non-active slide at `z-index: auto/0`.
3. **Index page — non-coverage area**: scroll above or below the coverage section. Verify
   background buttons (Values section cards, Fleet "View Full Fleet" button, Contact form
   submit) are clickable (coverage-sticky has `is-visible` removed).
4. **Other pages (services, tracking, contact, fleet, border-clearance, 404)**: the existing
   inline `<style>` fix remains in effect. Verify page buttons are clickable as before.
5. **Mobile viewport (≤768 px)**: check coverage-slide column layout, label padding, and
   map frame sizing. Progress labels are hidden on mobile — verify they don't reappear after
   rotation. Verify slide content scrolling and page buttons remain reachable.
6. **Transition**: scroll through 2+ slides rapidly. Verify quick class mutation doesn't leave
   a stale slide with `pointer-events: auto` blocking clicks on the now-active slide.
